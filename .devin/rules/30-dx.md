# Rule: Developer Experience (DX) for All Projects

**ALWAYS** apply the Developer Experience skill and workflow when setting up or improving a project. Developer experience is user experience for developers — every friction point costs time and morale.

## Skill
`~/.codeium/windsurf/skills/developer-experience.md`

## Workflow
`~/.codeium/windsurf/windsurf/workflows/dx.md` — invoke with `/dx`

## Sub-Agent
`~/.codeium/windsurf/windsurf/sub-agents/dx-optimizer.md` (parent: Infrastructure Engineer)

## How to follow this rule:
1. When setting up a project, invoke the `/dx` workflow
2. Follow the workflow steps in order: Setup → VSCode → Code Quality → Fast Feedback → Error Messages → Onboarding → Path Aliases → Scripts → CI/CD → Metrics → Document
3. Always ensure one-command setup — `npm install && npm run dev` works in under 5 minutes
4. Always set up VSCode integration — settings, extensions, snippets, launch config
5. Always automate code quality — ESLint, Prettier, Husky, lint-staged on pre-commit
6. Always use Vite or Turbopack for fast dev server — cold start < 2s, HMR < 200ms
7. Always write clear, actionable error messages with context
8. Always track DX metrics — cold start, HMR, test speed, build time, CI time

## When this rule applies:
- Setting up a new project
- Improving onboarding or tooling
- Reducing build times or friction
- Setting up VSCode integration or CI
- User asks about developer experience

## When this rule does NOT apply:
- Quick prototypes or throwaway scripts
- User explicitly says to skip DX setup
