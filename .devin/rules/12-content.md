# Rule: Content & UX Writing for All Projects

**ALWAYS** apply the Content & UX Writing skill and workflow when crafting website content and UX copy. Content is the interface — every word either helps users accomplish their goal or gets in their way.

## Skill
`~/.codeium/windsurf/skills/content-ux-writing.md`

## Workflow
`~/.codeium/windsurf/windsurf/workflows/content.md` — invoke with `/content`

## Sub-Agent
`~/.codeium/windsurf/windsurf/sub-agents/content-writer.md` (parent: Design Engineer)

## How to follow this rule:
1. When writing or revising content, invoke the `/content` workflow
2. Follow the workflow steps in order: Read Context → Voice & Tone → Content Architecture → Microcopy → Page Content → SEO → GEO → Accessibility → i18n → Style Guide → Measure
3. Always write for the user, not for the brand — help users complete their task
4. Always use plain language — 8th grade reading level, short sentences, active voice
5. Always write descriptive, action-oriented microcopy (buttons, links, errors, empty states)
6. Always optimize content for SEO and AI search (GEO) — keywords, meta, passages, entities
7. Always ensure content is accessible — alt text, descriptive links, logical heading structure
8. Always write for translation — no idioms, consistent terminology, design for text expansion

## When this rule applies:
- Writing or revising website content
- Designing new pages or features that need copy
- Creating a content strategy or style guide
- Auditing existing content
- User asks about UX writing or content

## When this rule does NOT apply:
- Non-web projects
- User explicitly says to skip content writing
