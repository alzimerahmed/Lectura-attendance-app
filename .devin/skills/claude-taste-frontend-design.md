# Claude Taste Frontend Design Skill

## Purpose
This skill encodes the design taste, preferences, and principles that produce **distinctive, intentional, non-generic frontend design**. It synthesizes Anthropic's official frontend design guidance, modern 2025-2026 web design trends, and a comprehensive catalog of AI design anti-patterns to avoid. Use this skill whenever building or redesigning any website UI to ensure the output looks like it was crafted by a human designer with a point of view — not generated by a template.

## Core Philosophy

Approach every design as the **design lead at a small studio known for giving every client a visual identity that could not be mistaken for anyone else's**. The client has already rejected proposals that felt templated and is paying for a distinctive point of view. Make deliberate, opinionated choices about palette, typography, and layout that are specific to the brief. Take at least one real aesthetic risk you can justify.

**The #1 rule:** If your design could belong to any project, it belongs to no project. Every choice must be grounded in the specific subject, audience, and purpose.

## Part 1: What to AVOID — The AI Slop Catalog

AI-generated design converges on predictable defaults. These are the fingerprints that make a site look machine-made. **Check every design against this catalog.**

### Color Anti-Patterns

| Pattern | AI Default | Instead |
|---|---|---|
| **Blue Primary** | `#3B82F6` (Tailwind blue-500) or `#6366F1` (indigo-500) | Pick a primary outside the 200-290° hue band. Earth tones, warm neutrals, greens, muted reds |
| **Blue-to-Purple Gradient** | `linear-gradient(to right, #2563EB, #7C3AED)` | Flat background, subtle texture, or gradient between adjacent hues |
| **Gray-50 Background** | `#F9FAFB` | Warm off-white like `#FEFCF8` or `#F5F0EB`, or a tinted neutral that relates to your primary |
| **Shallow Palette** | 3-4 colors only | 8-12 colors: primary, secondary, accent, background, surface, text, muted, success, warning, error |
| **White Cards on Gray** | `#FFFFFF` cards on `#F9FAFB` bg (1.01:1 contrast) | Tinted surface like `#F4EDE4` on a distinctly different background, or drop the card container |
| **Oversaturated Accents** | `yellow-400`, `green-500`, `red-500` | Desaturate with OKLCH — hold perceptual lightness while dropping chroma. Muted terracotta `#C4553A` > pure red `#EF4444` |
| **Gradient Buttons** | Linear gradient shifting between saturated colors | Flat-colored buttons with subtle hover change |
| **Colored Badge Pills** | `rounded-full bg-blue-100 text-blue-800` | Plain text with `tracking-widest uppercase`, or a simple `border-bottom` treatment |
| **Pure Black/White Text** | `#000000` / `#FFFFFF` | Warm or cool off-blacks (`#1a1612`, `#141820`) and off-whites |
| **Tailwind Semantic Colors** | `green-500` for success, `red-500` for error | Custom semantic colors tuned to your palette |

### Typography Anti-Patterns

| Pattern | AI Default | Instead |
|---|---|---|
| **Inter as Only Font** | Inter everywhere (70%+ of AI output) | Body font outside top 10 Google Fonts. IBM Plex Sans, Source Serif 4, Instrument Serif, DM Sans, Manrope |
| **System-UI Font Stack** | `font-family: system-ui, -apple-system, sans-serif` | Load at least a body face and a display face — two intentional typefaces |
| **Uniform Type Scale** | `h1: 3rem, h2: 2.25rem, h3: 1.5rem, body: 1rem` | Modular scale with ratio 1.25 or 1.333, or hand-pick sizes that create tension |
| **No Letter-Spacing** | Same tracking everywhere | Headings >2rem: `letter-spacing: -0.03em`. Text <0.875rem: `letter-spacing: 0.01em` |
| **Bold for All Headings** | `font-weight: 700` on everything | Vary weight — h1 at 400 italic, h2 at 600, h3 at 500. Weight variation creates rhythm |
| **text-gray-600 Body** | `#4B5563` for all secondary text | Custom muted color — warm gray `#6B6560` reads more human |
| **No Display Font** | One family for everything | Pair a display face for headings with a body face for text. Serif + sans is classic |
| **Uniform Line Height** | `leading-7` or `leading-relaxed` everywhere | Display: 1.1. Body: 1.6. Small: 1.5. Caption: 1.4 |
| **No Prose Styling** | No max-width, no paragraph spacing | Cap prose at `65ch`. Add `text-rendering: optimizeLegibility`. Use `1.5em` paragraph spacing |
| **Centered Text Everywhere** | `text-center` on every section | Left-align by default. Center only the hero heading and CTA |
| **No Font Features** | No OpenType features | `font-feature-settings: "kern", "liga", "calt"` on body. Stylistic sets where supported |
| **All-Caps Without Tracking** | Uppercase with no extra spacing | Always pair uppercase with `tracking-widest` or `tracking-wider` |

### Layout Anti-Patterns

| Pattern | AI Default | Instead |
|---|---|---|
| **Three-Column Equal Grid** | `grid-cols-3 gap-6` with identical children | Asymmetric grids (2/3 + 1/3), definition lists, varied-width columns |
| **max-w-7xl Everywhere** | Same centered container on every section | Vary max-width: `max-w-3xl` for text, `max-w-6xl` for features, full-bleed for hero |
| **Symmetric Padding** | `py-24 px-6` on every section | Vary it: `pt-32 pb-20` on one, `pt-16 pb-24` on next. Build vertical rhythm through asymmetry |
| **Template Section Order** | Hero → Features → Testimonials → Pricing → CTA → Footer | Reorder around your content. Lead with a case study. Put pricing before features |
| **All Content Centered** | `mx-auto text-center` everywhere | Left-align body content. Use `ml-[8%]` or `ml-[12%]` for intentional off-center placement |
| **Equal-Height Cards** | Grid stretch forcing all cards same height | `align-items: start` — let cards size to content. Varied heights read organic |
| **Sticky Nav with Blur** | `sticky top-0 backdrop-blur-md bg-white/80` | Solid-background nav, hide-on-scroll/reveal-on-scroll-up, or minimal text-only header |
| **No Full-Bleed** | Everything stays in its container | Let key elements break out. Full-bleed image or viewport-spanning background is visual punctuation |
| **4-Column Footer** | Logo column + 3 link columns + copyright | Single-column, two-row, or minimal footer with just copyright and essential links |
| **No Whitespace** | Every section filled | Generous whitespace between sections. Let a heading stand alone with 200px below it |
| **No Off-Grid Elements** | Everything perfectly on the grid | Occasional negative margins, overlapping elements, absolute-positioned accents |
| **Z-Pattern Forever** | Image right/text left, then alternating | Break the alternation. Two consecutive left-aligned sections. Drop a full-width section between |

### Animation Anti-Patterns

| Pattern | AI Default | Instead |
|---|---|---|
| **Fade-Up on Scroll** | `opacity: 0, y: 20` → `opacity: 1, y: 0` on every element | No animation for most content. Reserve for one hero element or key interaction. Stillness is a craft signal |
| **Hover Scale 1.05** | `transform: scale(1.05)` + shadow on hover | Subtle background-color shifts, border-color transitions, or nothing |
| **Stagger 0.1s** | Every child delayed by exactly 0.1s | Irregular stagger (0.05s, 0.12s, 0.08s), or animate groups |
| **Duration 300ms** | `transition-duration: 300ms` everywhere | Shorter (150ms) for small UI, longer (500ms) for large layout transitions |
| **Ease-in-out Everywhere** | `transition-timing-function: ease-in-out` | `cubic-bezier(0.22, 1, 0.36, 1)` for entrances, `cubic-bezier(0.55, 0, 1, 0.45)` for exits |
| **Infinite Pulse** | `animate-pulse` / `animate-bounce` on badges | Static indicator, or a single subtle flash on state change |
| **Parallax Hero** | Hero bg scrolling at different rate | Static hero image, or subtle CSS-only effect like slight scale on scroll |
| **Counting Numbers** | Stats counting up from 0 on scroll | Show the number. Count-up adds no information and delays comprehension |
| **Typewriter Hero** | Hero text typing out character by character | Show text immediately. If entrance needed, use one fade or clip-path reveal |
| **Floating Icons** | Decorative icons floating up and down infinitely | Keep decorative elements still. Animation should respond to interaction |
| **Skeleton Shimmer** | Gray-to-light-gray shimmer sweep | Simple opacity pulse or solid gray placeholder |
| **No reduced-motion** | Animations with no `prefers-reduced-motion` guard | Always wrap animations in `@media (prefers-reduced-motion: reduce)` |

### Component Anti-Patterns

| Pattern | AI Default | Instead |
|---|---|---|
| **Icon + Heading + Paragraph Card** | Icon in colored circle, heading, paragraph | Numbered list, definition list, table, or flowing paragraph with inline emphasis |
| **Badge + H1 + Subtitle + 2 Buttons Hero** | Small badge pill, large heading, subtitle, primary + ghost buttons | Simplify. One heading and one button. Or heading with inline link. Drop the badge |
| **Testimonial Cards with Circle Avatars** | 3 cards with circular avatar, name, title, quote | One large blockquote. Drop avatars. Feature one testimonial prominently |
| **Pricing Cards with Popular Badge** | 3 tiers, middle is "popular" with colored badge | Comparison table, or highlight recommended plan with genuinely different layout |
| **FAQ Accordion with Chevrons** | Questions expanding behind rotating chevron | Show all answers by default (under 8). Or plain toggle without chevron. Or flowing document |
| **Newsletter Input + Inline Button** | Email input with button glued to right edge | Stack input and button vertically. Or "Get updates" link opening a modal |
| **Stats with Big Numbers** | Row of 3-4 big numbers with labels | Fold stats into prose. "Used by over 10,000 teams across 150 countries" |
| **Logo Cloud Grayscale** | Client logos grayscale, hover reveals color | Logos at full color, small, in a plain row. Or name clients in a sentence |
| **CTA with Gradient Background** | Blue-to-purple gradient, centered white text, white button | Brand background color. Left-align text. Use underlined link, not button |
| **Tabs with Sliding Underline** | Active tab has underline that slides between tabs | Filled tab backgrounds, vertical tab lists, or segmented controls |
| **Modal with Backdrop Blur** | `backdrop-blur` over darkened backdrop | Plain dark overlay without blur, slide-in side panels, or inline expansion |

## Part 2: What to DO — Design Principles & Modern Best Practices

### 2.1 Ground It in the Subject

If the brief doesn't pin down what the product or subject is, **pin it yourself before designing**:
1. Name one concrete subject
2. Identify its audience
3. Define the page's single job
4. State your choice

The subject's own world — its materials, instruments, artifacts, and vernacular — is where distinctive choices come from. Build with the brief's real content and subject matter throughout.

### 2.2 The Hero Is a Thesis

Open with the most characteristic thing in the subject's world, in whatever form makes sense:
- A headline, an image, an animation, a live demo, an interactive moment
- Be deliberate: a big number with a small label, supporting stats, and a gradient accent is the **template answer** — only use if that's truly the best option
- The hero should immediately communicate what makes this project unique

### 2.3 Typography Carries Personality

**Font Selection — Never use:**
- Inter, Roboto, Open Sans, Lato, Geist, default system fonts

**Impact choices by aesthetic:**
- **Code/Technical:** JetBrains Mono, Fira Code, Space Grotesk, IBM Plex Mono
- **Editorial:** Playfair Display, Crimson Pro, Fraunces, Instrument Serif, Newsreader
- **Startup/Modern:** Clash Display, Satoshi, Cabinet Grotesk, General Sans
- **Technical/Clean:** IBM Plex family, Source Sans 3, DM Sans
- **Distinctive:** Bricolage Grotesque, Obviously, Manrope, Sora

**Pairing principle:** High contrast = interesting.
- Display + monospace
- Serif + geometric sans
- Variable font across weights

**Use extremes:** 100/200 weight vs 800/900, not 400 vs 600. Size jumps of 3x+, not 1.5x.

**Type scale:** Use a modular scale with ratio 1.25 or 1.333. Example:
```
--text-xs: 0.75rem (12px)
--text-sm: 0.875rem (14px)
--text-base: 1rem (16px)
--text-lg: 1.25rem (20px)
--text-xl: 1.5rem (24px)     /* ratio 1.25 */
--text-2xl: 1.875rem (30px)
--text-3xl: 2.344rem (37.5px)
--text-4xl: 2.93rem (47px)
--text-5xl: 3.66rem (59px)
--text-6xl: 4.58rem (73px)
```

**Line height by context:**
- Display headings: 1.1-1.3
- Body text: 1.5-1.7
- Small/UI text: 1.4-1.5

**Letter spacing by context:**
- Headings >2rem: `-0.02em` to `-0.04em`
- Body: `0` to `0.01em`
- Small text <0.875rem: `0.02em` to `0.05em`
- Uppercase labels: `0.1em` to `0.15em`

**Optimal line length:** 60-75 characters (~30-35em at 16px)

**Always enable:**
```css
font-feature-settings: "kern", "liga", "calt";
text-rendering: optimizeLegibility;
```

**For headings:**
```css
h1, h2, h3 { text-wrap: balance; }
```

### 2.4 Color & Theme — Commit to a Cohesive Aesthetic

**Palette construction:**
1. Start with a dominant color (60% of the design)
2. Add a secondary color (30%)
3. Add a sharp accent (10%) — this is where personality lives
4. Dominant colors with sharp accents outperform timid, evenly-distributed palettes

**Sources for distinctive palettes:**
- Pantone colors from past decades
- Film LUTs and cinema color grading
- Paint chips from hardware stores
- Print magazines from countries with different web aesthetics
- Nature — geological, botanical, marine color systems
- Cultural aesthetics — Scandinavian, Japanese, Mediterranean, etc.

**Neutrals should have hue:**
- Warm off-white: `#FEFCF8`, `#F5F0EB`, `#F4EDE4`
- Cool off-white: `#F4F5F7`, `#EDF0F3`
- Warm off-black: `#1A1612`, `#1E1A15`
- Cool off-black: `#141820`, `#0F1419`
- Warm gray: `#6B6560`, `#8B8580`
- Cool gray: `#5C6470`, `#7A8290`

**Use CSS variables for consistency:**
```css
:root {
  --primary: #2D5A3D;
  --primary-dark: #1E3F2B;
  --secondary: #C4553A;
  --accent: #D4A574;
  --background: #FEFCF8;
  --surface: #F4EDE4;
  --text: #1A1612;
  --text-muted: #6B6560;
  --border: #E0DAD0;
  --success: #4A7C59;
  --warning: #C4553A;
  --error: #A63D40;
}
```

**Dark mode** (design separately, don't just invert):
```css
@media (prefers-color-scheme: dark) {
  :root {
    --background: #1A1917;    /* not pure black */
    --surface: #252420;
    --text: #E8E0D6;
    --muted: #8B8580;
    --primary: #5B9E74;       /* lighter, less saturated */
    --accent: #D4745A;        /* lighter, less saturated */
  }
}
```

### 2.5 Layout & Structure — Information Architecture

**Structure is information.** Structural devices — numbering, eyebrows, dividers, labels — should encode something true about the content, not decorate it.

**Numbered markers (01 / 02 / 03)** are only appropriate if the content actually IS a sequence — a real process or typed timeline where order carries information. Question whether they make sense before using them.

**Layout principles:**
- Vary section padding: `pt-32 pb-20` on one, `pt-16 pb-24` on next
- Vary max-width between sections: narrow for text, wide for features, full-bleed for hero
- Use asymmetric grids: `5fr 3fr` beats `repeat(3, 1fr)`
- Left-align by default; center only on purpose
- Use generous whitespace as a design element — let a heading stand alone with 200px below it
- Let key elements break out of containers for visual punctuation
- Vary density: maximalist on brand pages, disciplined on task-oriented screens

**Responsive approach — Mobile-first:**
- Design for 360px first, then enhance upward
- Touch targets: minimum 48x48px (Material) or 44x44px (Apple HIG)
- Use `clamp()` for fluid typography
- Use container queries for component-level responsiveness
- Don't just collapse grids to 1 column — try 2-column on tablet, horizontal scroll on mobile, accordion patterns

### 2.6 Motion & Interaction — Deliberate, Not Decorative

**Leverage motion deliberately.** Think about where and if animation can serve the subject:
- A page-load sequence
- A scroll-triggered reveal
- Hover micro-interactions
- Ambient atmosphere

**An orchestrated moment usually lands harder than scattered effects.** Choose what the direction calls for. Sometimes less is more — extra animation contributes to the feeling that the design is AI-generated.

**One well-orchestrated page load** with staggered reveals creates more delight than scattered micro-interactions everywhere.

**Animation rules:**
- Animate only `transform` and `opacity` for GPU-composited smoothness
- Never animate `width`, `height`, `top`, `left`, `margin`, `padding` (triggers layout recalculation)
- Use `will-change: transform` sparingly — only right before animation begins, remove after
- Custom cubic-bezier curves over built-in keywords:
  - Entrances: `cubic-bezier(0.22, 1, 0.36, 1)`
  - Exits: `cubic-bezier(0.55, 0, 1, 0.45)`
- Vary duration by element: 150ms for small UI, 400-500ms for large layout transitions
- Every action needs visual response in under 100ms
- Always include `prefers-reduced-motion` support

**For React:** Use Motion library (Framer Motion) when available.
**For HTML:** Prioritize CSS-only solutions.

### 2.7 Backgrounds — Atmosphere and Depth

Create atmosphere rather than defaulting to solid colors:
- Layer CSS gradients (subtle, directional, restrained)
- Use geometric patterns
- Add contextual effects that match the aesthetic
- Micro-gradients: barely perceptible color shifts that imply lighting
- Gradient borders and gradient text on dark backgrounds (used sparingly)
- Frosted glass (`backdrop-filter: blur()`) for floating elements — but only on visually rich backgrounds

**Depth without skeuomorphism:**
- Stack 2-3 shadows at different blur radii (small + medium + large) for physically convincing elevation
- Smallest shadow: crisp edge definition
- Largest shadow: ambient cast shadow
- Translucency and layering create hierarchy without decorative textures

### 2.8 Copy and Content — Words Are Design Material

Words appear in a design to make it easier to understand. Bring the same intentionality to copy as to spacing and color.

- **Write from the user's side of the screen.** Name things by what people control and recognize, not by how the system is built
- **Active voice as default.** "Save changes," not "Submit." "Publish" produces "Published."
- **Be specific, not clever.** Describe what something does in plain terms
- **Errors don't apologize** and are never vague. Explain what went wrong and how to fix it
- **Empty states are invitations to act**, not mood pieces
- **Keep register conversational and tuned:** plain verbs, sentence case, no filler
- **Let each element do exactly one job.** A label labels, an example demonstrates

### 2.9 Accessibility — Design Quality, Not a Checkbox

WCAG 2.2 AA is the practical bar:
- **Contrast:** 4.5:1 for normal text, 3:1 for large text and UI components
- **Focus states:** Visible focus indicators for keyboard navigation — custom `:focus-visible` styles
- **Keyboard nav:** Every interactive element accessible with Tab, Enter, arrow keys
- **Semantic HTML:** Proper heading hierarchy, HTML5 landmarks (`header`, `nav`, `main`, `footer`), ARIA only where needed
- **Alt text:** Descriptive, not "image-123.jpg"
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` — disable animations
- **Forms:** Persistent labels (not placeholder-only), inline validation with specific human error messages, single-column layout with top-aligned labels

## Part 3: Craft Signals — What Makes Design Look Human

These positive patterns signal craftsmanship. Their presence immediately raises perceived quality.

| Signal | Implementation |
|---|---|
| **Custom Selection Colors** | `::selection { background-color: var(--primary); color: var(--background); }` |
| **Custom Focus-Visible** | `:focus-visible { outline: 2px solid var(--primary); outline-offset: 3px; }` |
| **Prefers-Reduced-Motion** | `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }` |
| **Custom Scrollbar** | `::-webkit-scrollbar { width: 8px; }` with track and thumb in your palette |
| **Print Styles** | `@media print { nav, footer { display: none; } body { color: #000; background: #fff; } }` |
| **Proper Dark Mode** | Separately designed dark palette with reduced chroma, not inverted colors |
| **Smooth Scroll with Check** | `@media (prefers-reduced-motion: no-preference) { html { scroll-behavior: smooth; } }` |
| **Hanging Punctuation** | `blockquote, .prose { hanging-punctuation: first last; }` |
| **Custom List Markers** | `ul li::before { content: "–"; color: var(--accent); font-weight: 600; margin-right: 0.75em; }` |
| **Tabular Figures** | `.data-table, .price, .stat { font-variant-numeric: tabular-nums; }` |
| **Font Smoothing** | `body { -webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale; }` |
| **Balanced Text Wrapping** | `h1, h2, h3 { text-wrap: balance; }` |
| **Container Queries** | `@container (min-width: 400px) { .card { flex-direction: row; } }` |
| **Custom Underline Styling** | `a { text-underline-offset: 3px; text-decoration-thickness: 1.5px; text-decoration-color: var(--accent); }` |

## Part 4: The Design Process

### Step 1: Brainstorm
Create a compact token system:
- **Color:** 4-6 named hex values describing the palette
- **Type:** Typefaces for 2+ roles (characterful display face used with restraint, complementary body face, utility face for captions/data if needed)
- **Layout:** One-sentence prose descriptions and ASCII wireframes to ideate and compare
- **Signature:** The single unique element this page will be remembered by

### Step 2: Self-Critique
Review the plan against the brief before building:
- If any part reads like the generic default you would produce for any similar page — **revise that part**
- Say what you changed and why
- Check against the AI slop catalog above — any matches?

### Step 3: Build
Only after confirming the relative uniqueness of the design plan:
- Follow the revised plan exactly
- Derive every color and type decision from it
- Be careful with CSS selector specificities — classes can cancel each other out

### Step 4: Critique Again
- Take screenshots if possible — a picture is worth 1000 tokens
- Consider Chanel's advice: before leaving the house, take a look in the mirror and remove one accessory
- Cut any decoration that does not serve the brief

### Restraint
**Spend your boldness in one place.** Let the signature element be the one memorable thing. Keep everything around it quiet and disciplined. Not taking a risk can be a risk itself.

Build to a quality floor without announcing it:
- Responsive down to mobile
- Visible keyboard focus
- Reduced motion respected
- WCAG 2.2 AA contrast

## Part 5: Known AI Default Clusters to Avoid

AI-generated design currently clusters around three looks. All three are legitimate for some briefs, but they are **defaults rather than choices** and appear regardless of subject:

1. **Warm cream background** (near `#F4F1EA`) with high-contrast serif display and terracotta accent
2. **Near-black background** with a single bright acid-green or vermilion accent
3. **Broadsheet-style layout** with hairline rules, zero border-radius, and dense newspaper-like columns

Where the brief pins down a visual direction, follow it exactly. Where it leaves an axis free, **don't spend that freedom on one of these defaults.**

Also avoid converging on:
- Space Grotesk across generations (it's becoming the new Inter)
- `from-blue-600 to-indigo-700` gradient hero
- `rounded-2xl` on everything
- `backdrop-blur-md` navigation
- `transition-all duration-300 ease-in-out` on every element

## Part 6: Performance as Design

Performance is a design constraint, not an engineering afterthought:

- **LCP < 2.5s** — usually determined by hero image. Optimize it, preload it, never lazy-load it
- **INP < 200ms** — avoid heavy JavaScript on main thread
- **CLS < 0.1** — set explicit `width` and `height` on all images
- **Image formats:** AVIF (best compression, 30-70% smaller than JPG) with WebP fallback. SVG for icons/logos
- **Font loading:** `font-display: swap`, preload critical fonts, use variable fonts where possible
- **Minimal JavaScript:** Partial hydration, islands architecture, server components
- **Critical resource preloading:** Fonts, critical CSS, hero images with `fetchpriority="high"`
- **A beautiful design that loads in 8 seconds is a failed design**

## Execution Instructions for Cascade

When this skill is activated during frontend development:

1. **Read the project's `research.md`** if it exists — it contains the design direction
2. **Follow the design process:** Brainstorm → Self-Critique → Build → Critique Again
3. **Check every design decision against the AI slop catalog** in Part 1
4. **Incorporate craft signals** from Part 3 into every project
5. **Take screenshots** of the result and critique them
6. **Vary your choices** — don't converge on the same fonts, colors, or layouts across projects
7. **When in doubt, choose the unexpected** — that's what separates human design from AI default
