# Website Research & Discovery Skill

## Purpose
This skill provides a comprehensive, structured research methodology for gathering every piece of information needed to design and build any kind of website. It reflects modern 2025-2026 research practices — using browser tools to visit and analyze reference sites, web search for industry trends, and structured documentation that can be referenced throughout the entire development process. Use this skill at the start of every new website project to ensure nothing is missed — from project discovery to visual design to technical architecture.

## When to Use
- Starting any new website project
- Redesigning or rebuilding an existing website
- When the user says "research" or "plan" a website
- When the user provides a reference website to clone or draw inspiration from
- Before writing any code for a new website

---

## Phase 1: Project Discovery

### 1.1 Project Type Identification
Identify and document the type of website:
- **Business/Corporate** — company site, agency, consultancy
- **E-commerce** — online store, marketplace, product catalog
- **Portfolio** — personal, agency, creative professional
- **Blog/Magazine** — content publication, news, editorial
- **SaaS/Web App** — dashboard, tool, platform
- **Landing Page** — product launch, campaign, lead gen
- **Educational** — course platform, tutorial site, LMS
- **Non-profit/NGO** — charity, foundation, community
- **Restaurant/Hospitality** — restaurant, hotel, travel
- **Real Estate** — property listings, agency
- **Event** — conference, wedding, festival
- **Personal Brand** — influencer, speaker, author
- **Other** — document any unique category

### 1.2 Stakeholder Questions
Ask the user (if not already provided):
1. What is the primary goal of this website? (sales, leads, awareness, portfolio, etc.)
2. Who is the target audience? (age, profession, interests, location)
3. What is the brand name and tagline?
4. Are there existing brand assets? (logo, colors, fonts, brand guide)
5. What feeling/mood should the website evoke? (luxury, playful, minimal, bold, calm)
6. List 3-5 competitor or reference websites
7. What pages/sections are needed?
8. What is the preferred timeline and budget?
9. Are there any must-have features? (booking, cart, blog, newsletter, multilingual, etc.)
10. What is the preferred tech stack or any constraints?

### 1.3 Scope Document
Produce a brief scope document summarizing:
- Project type
- Primary and secondary goals
- Target audience profile
- Key features list
- Page/section list
- Known constraints

## Phase 2: Competitive & Reference Research

### 2.1 Competitor Analysis
For each competitor/reference website provided:
1. **Visit the website** using browser tools (navigate, snapshot, screenshot)
2. **Document the following:**
   - Overall layout structure (hero, sections, footer)
   - Navigation pattern (sticky, mega menu, hamburger, side)
   - Color scheme (primary, secondary, accent, background, text)
   - Typography (heading font, body font, sizes, weights)
   - Imagery style (photography, illustrations, 3D, icons, abstract)
   - Animation/interaction patterns (hover effects, scroll animations, parallax)
   - Content tone and voice (formal, casual, technical, persuasive)
   - CTA strategy (placement, wording, design)
   - Social proof elements (testimonials, reviews, logos, case studies)
   - Unique/s standout features
   - Mobile responsiveness approach
   - Page load speed impression
   - SEO structure (meta titles, headings hierarchy, URL structure)

### 2.2 Industry Trends Research
- Search the web for current design trends in the identified industry
- Look for award-winning sites in the same category (Awwwards, CSS Design Awards, etc.)
- Note common patterns and conventions users expect
- Identify opportunities to differentiate

### 2.3 Inspiration Gathering
- Collect 3-5 visual references (screenshots, links)
- Note specific elements to borrow or adapt
- Create a mood board description (colors, textures, imagery style, typography feel)

## Phase 3: Content Strategy

### 3.1 Content Audit & Planning
For each planned page/section, document:
1. **Page name and purpose**
2. **Key message** (one sentence summary)
3. **Content blocks** (hero text, features, about, services, testimonials, FAQ, CTA, etc.)
4. **Copy direction** (tone, reading level, length)
5. **Media needs** (images, videos, icons, illustrations)
6. **Data sources** (APIs, databases, CMS, static content)

### 3.2 Information Architecture
- Create a sitemap (all pages and their hierarchy)
- Define the primary navigation structure
- Define footer links
- Plan URL structure
- Identify cross-linking opportunities

### 3.3 SEO Content Planning
- Identify primary keywords for each page
- Plan meta title and description for each page
- Define heading structure (H1, H2, H3) for each page
- Plan internal linking strategy
- Identify schema markup opportunities (LocalBusiness, Product, Article, FAQ, etc.)

### 3.4 Copywriting Guidelines
- Define brand voice (professional, friendly, authoritative, playful, etc.)
- Define tone rules (what to say, what to avoid)
- Create a messaging hierarchy (what comes first, second, third)
- Plan CTA copy variations
- Document any industry-specific terminology to use or avoid

## Phase 4: Visual Design Research

### 4.1 Color Palette
Research and define:
1. **Primary color** — main brand color (with hex/OKLCH values)
2. **Secondary color** — supporting color
3. **Accent color** — for CTAs, highlights, links
4. **Background colors** — light/dark variants
5. **Text colors** — primary text, secondary text, muted text
6. **Semantic colors** — success, warning, error, info
7. **Color ratios** — where each color is used (e.g., 60% neutral, 30% primary, 10% accent)
8. **Dark mode variant** — if applicable

### 4.2 Typography System
Research and define:
1. **Heading font** — family, fallback, weights used
2. **Body font** — family, fallback, weights used
3. **Mono font** — if needed (code, data)
4. **Display font** — if needed (hero, large numbers)
5. **Type scale** — sizes for h1-h6, body, small, caption (in rem)
6. **Line height** — for headings, body, UI text
7. **Letter spacing** — for headings, buttons, labels
8. **Font loading strategy** — self-host, Google Fonts, variable fonts, preload

### 4.3 Spacing & Layout System
1. **Spacing scale** — base unit, scale steps (e.g., 4px, 8px, 16px, 24px, 32px, 48px, 64px, 96px)
2. **Container widths** — max-width for content, full-width sections
3. **Grid system** — columns, gutters, breakpoints
4. **Section padding** — vertical rhythm between sections
5. **Border radius** — scale for cards, buttons, inputs, images

### 4.4 Imagery & Media Direction
1. **Photography style** — real photos, stock, custom shoot, none
2. **Image treatment** — filters, overlays, aspect ratios, rounded corners
3. **Illustration style** — flat, 3D, hand-drawn, isometric, none
4. **Icon set** — Lucide, Heroicons, Phosphor, custom, etc.
5. **Video/animation** — background video, explainer, micro-interactions
6. **Image optimization strategy** — formats (WebP, AVIF), lazy loading, srcset

### 4.5 Component Design Direction
For each component type, document the visual direction:
- **Buttons** — style, sizes, states (hover, active, disabled), variants
- **Cards** — style, shadow, border, hover behavior
- **Forms/Inputs** — style, validation display, focus states
- **Navigation** — style, mobile behavior, dropdown style
- **Modals/Dialogs** — style, animation, backdrop
- **Hero section** — layout, content, background treatment
- **Footer** — layout, content, style
- **Testimonials** — layout, style, carousel or grid
- **Pricing tables** — if applicable, style, toggle behavior

### 4.6 Motion & Interaction Design
1. **Page load animations** — fade-in, slide-up, stagger
2. **Scroll-triggered animations** — reveal patterns, parallax
3. **Hover interactions** — scale, color change, underline, tooltip
4. **Transition timing** — duration, easing functions
5. **Micro-interactions** — button press, form submit, toggle, accordion
6. **Cursor effects** — if any custom cursor behavior

## Phase 5: UX & User Flow Research

### 5.1 User Journey Mapping
For each primary user persona:
1. **Entry point** — how they arrive (search, social, direct, ad)
2. **First impression** — what they see first (hero, value prop)
3. **Key actions** — what they need to do (buy, contact, sign up, read)
4. **Decision path** — pages they visit in order
5. **Conversion point** — where they convert
6. **Exit** — post-conversion experience

### 5.2 Wireframe Plan
For each page, create a text-based wireframe description:
1. **Above the fold** — what's visible without scrolling
2. **Content sections** — in order, top to bottom
3. **Sidebar (if any)** — content and position
4. **CTA placement** — where conversion actions live
5. **Mobile layout** — how sections stack and reorder

### 5.3 Accessibility Planning
1. **Color contrast** — ensure WCAG AA (4.5:1 text, 3:1 large text)
2. **Focus states** — visible focus indicators for keyboard nav
3. **Semantic HTML** — proper heading hierarchy, landmarks, roles
4. **Alt text strategy** — for all meaningful images
5. **Keyboard navigation** — tab order, skip links, no keyboard traps
6. **ARIA** — where needed and where to avoid
7. **Reduced motion** — respect `prefers-reduced-motion`
8. **Screen reader testing plan**

## Phase 6: Technical Research

### 6.1 Technology Stack Selection
Based on project needs, recommend:
1. **Framework** — Next.js, Astro, React, Vue, SvelteKit, plain HTML/CSS/JS
2. **Styling** — Tailwind CSS, CSS Modules, styled-components, plain CSS
3. **UI Components** — shadcn/ui, Radix, Headless UI, custom
4. **Animations** — Framer Motion, GSAP, CSS animations, Lottie
5. **CMS** — Sanity, Contentful, Strapi, Markdown, none
6. **E-commerce** — Shopify, Medusa, Stripe, Snipcart, none
7. **Forms** — Resend, Formspree, custom API, none
8. **Analytics** — Google Analytics, Plausible, Umami, none
9. **Hosting/Deployment** — Vercel, Netlify, Cloudflare, self-host
10. **Database** — Supabase, PlanetScale, SQLite, none
11. **Auth** — Clerk, Auth.js, Supabase Auth, none

### 6.2 Performance Budget
1. **Target Lighthouse score** — Performance, Accessibility, Best Practices, SEO
2. **Bundle size target** — JS, CSS, total
3. **Image budget** — max size per image, total per page
4. **Font budget** — max number of font files, total size
5. **Third-party scripts** — minimize, defer/async
6. **Caching strategy** — static, ISR, on-demand revalidation

### 6.3 SEO Technical Plan
1. **Meta tags** — title, description, OG, Twitter cards for each page
2. **Sitemap.xml** — generation strategy
3. **Robots.txt** — rules
4. **Canonical URLs** — strategy
5. **Structured data** — schema.org types to implement
6. **Open Graph assets** — images per page
7. **Favicon set** — sizes and formats

### 6.4 Responsive Breakpoints
Define breakpoints:
- **Mobile** — 320px to 480px
- **Tablet** — 481px to 768px (or 1024px)
- **Desktop** — 769px+ (or 1025px+)
- **Wide** — 1280px+ or 1440px+
- Document mobile-first or desktop-first approach

## Phase 7: Deliverables Checklist

After completing all research phases, produce a **Research Document** containing:

- [ ] Project scope summary
- [ ] Competitor analysis report (3-5 sites analyzed)
- [ ] Industry trends summary
- [ ] Mood board / visual direction description
- [ ] Sitemap and information architecture
- [ ] Page-by-page content plan with copy direction
- [ ] SEO keyword and meta plan
- [ ] Color palette (with hex/OKLCH values)
- [ ] Typography system (fonts, sizes, weights)
- [ ] Spacing and layout system
- [ ] Component design direction
- [ ] Motion and interaction plan
- [ ] User journey maps
- [ ] Wireframe descriptions for each page
- [ ] Accessibility plan
- [ ] Recommended tech stack
- [ ] Performance budget
- [ ] Technical SEO plan
- [ ] Responsive breakpoint definitions

Save this document as `research.md` in the project root so it can be referenced throughout development.

## Execution Instructions for Cascade

When this skill is activated:

1. **Read the user's project context** — check for existing files, README, prompt.md, or any project description
2. **Ask clarifying questions** from Phase 1.2 if information is missing
3. **Use browser tools** (navigate, snapshot, screenshot) to visit competitor/reference sites
4. **Use web search** to research industry trends and find inspiration
5. **Compile all findings** into a structured `research.md` document
6. **Save the research document** in the project root directory
7. **Summarize key findings** to the user and ask for confirmation before proceeding to development
8. **Reference the research document** throughout the entire development process to ensure consistency

### Tool Usage Guidelines
- Use `mcp6_browser_navigate` to visit reference websites
- Use `mcp6_browser_snapshot` to capture page structure
- Use `mcp6_browser_take_screenshot` to capture visual references
- Use `search_web` to research industry trends and find award-winning sites
- Use `read_url_content` to read content from reference pages
- Use `write_to_file` to save the research document
- Use `code_search` to understand any existing project code
